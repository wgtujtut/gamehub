# GameHub — паспорт проекта

Игровая панель для Windows: своё окно (pywebview, движок Edge) + иконка в трее. Распространяется установщиком через GitHub Releases (github.com/wgtujtut/gamehub, публичный).
Сделан 2026-10-07 лично для пользователя, раздаёт друзьям. Спецификация модулей и формат API — [SPEC.md](SPEC.md).

## Что умеет
- Учёт времени в играх: сам находит игры Steam (все библиотеки), Epic, Тарков (по реестру) и свои из настроек; процесс игры = exe внутри папки игры.
- Статистика: сегодня/неделя/месяц, серия дней, тепловая карта года, по часам и дням недели, сессии с пингом.
- Лаунчер: все игры с обложками (локальный кэш Steam), запуск, папка, «давно не играл — можно освободить X ГБ».
- Халява: Epic (бесплатно сейчас и скоро) + GamerPower (Steam/Epic/GOG), уведомление о новых.
- Режим игры: при запуске игры — план питания «Максимальная производительность», по желанию закрывает тяжёлые программы; после игры возвращает как было.
- Чистка кэшей (temp старше суток, шейдеры, Discord, браузеры, Steam, pip), пинг-монитор, лимит времени в день.
- Автообновление: раз в сутки смотрит последний релиз на GitHub, плашка «Обновить» → тихая установка и перезапуск.

## Запуск и сборка
- Пользователь работает с **установленной** версией (D:\Programs\GameHub или %LOCALAPPDATA%\Programs\GameHub), автозапуск — ключ реестра HKCU\...\Run `GameHub.exe --hidden`.
- Из исходников: `.venv\Scripts\python.exe app.py` (окно), `app.py --no-window` (только сервер + браузер). Перед этим закрыть установленную (трей → Выход), иначе второй запуск просто покажет её окно.
- Тесты: `.venv\Scripts\python.exe -m pytest -q` (папка данных в тестах — временная, через GAMEHUB_DATA).
- Сборка: `.venv\Scripts\python.exe build.py` → `dist\GameHub-Setup-<версия>.exe` (PyInstaller onedir + Inno Setup из D:\Programs\InnoSetup6).
- Релиз: поднять `VERSION` в updater.py → build.py → коммит → `gh release create v<версия> dist\GameHub-Setup-<версия>.exe` (gh в D:\Programs\GitHubCLI). Имя файла должно быть `GameHub-Setup-x.y.z.exe` — иначе автообновление его не возьмёт.
- Подпись: build.py подписывает GameHub.exe и установщик самодельным сертификатом «CN=GameHub (wgtujtut)» из хранилища Cert:\CurrentUser\My (отпечаток — `SIGNER_THUMBPRINT` в updater.py, действует до 2051). Автообновление (с 1.0.2) ставит только файл с этой подписью. Без сертификата на этом ПК релиз собрать нельзя; если он потерян — новый сертификат, новый отпечаток в updater.py, и друзьям один раз обновиться вручную.

## Устройство
- `app.py` — класс Hub (состояние и операции API), фоновые потоки (трекер, пинг, раздачи, библиотека, обновления), трей (`run_tray`), запуск (`main`).
- Окно панели — отдельный процесс `GameHub.exe --window` (`WindowProc`, `run_window_process`): адрес с ключом передаётся через переменную окружения GAMEHUB_URL. Крестик закрывает процесс окна целиком — движок Edge (~400 МБ) выгружается, в трее остаётся один процесс ~50 МБ. Лог окна — window.log.
- Нагрузка: пинг идёт только во время игры или пока панель открыта (+2 мин); панель опрашивает сервер раз в 5 с и только видимой, перерисовывает блоки только при изменении данных; powercfg — не чаще раза в минуту; SQLite в WAL с synchronous=NORMAL.
- `server.py` — HTTP API на 127.0.0.1, первый свободный порт из 8790–8799. Проверка Host; все /api/* только с заголовком `X-GameHub: <ключ>`. Ключ создаётся при каждом запуске (`secrets.token_urlsafe`), окно открывает панель с `?t=<ключ>`, фронт забирает его в sessionStorage и убирает из адреса; порт и ключ лежат в `%APPDATA%\GameHub\instance.json` для второго запуска.
- `updater.py` — VERSION, проверка релиза, скачивание установщика только с github.com/wgtujtut/gamehub/releases/download/.
- Модули по задачам: config, library, db, stats, tracker, deals, notify, gamemode, cleaner, net. Фронтенд — `web/` (ванильный JS).
- Данные пользователя: `%APPDATA%\GameHub` — gamehub.db, config.json, gamehub.log. Битый config.json откладывается в config.broken.json.
- Второй запуск берёт порт только из instance.json (не перебирает диапазон — ключ не уйдёт чужой программе на соседнем порту), просит работающий GameHub открыть окно и разрешает ему встать поверх (AllowSetForegroundWindow).

## Важно
- Текст из интернета (раздачи) в интерфейс — только через textContent; в PowerShell-уведомления — только через переменные окружения.
- Чистка не заходит в ссылки/junction и не удаляет сами папки-цели, только содержимое; `cleaner.is_safe_root` не даёт чистить корни дисков, профиль, Windows, Program Files (защита от кривых TEMP/PIP_CACHE_DIR).
- Аудит безопасности 2026-10-07 (методики Trail of Bits): исправления в 1.0.1. С 1.0.2 обновления подписаны и проверяются по отпечатку. Принятый риск: заброшенный `proxy-tools` в зависимостях pywebview.
- Повторный аудит 2026-10-07 скилами Trail of Bits (insecure-defaults — вручную по корпусу, т.к. нет Workflow-инструмента; sharp-edges; supply-chain-risk-auditor — 0 известных уязвимостей в 23 зависимостях). Исправлено: ключ только порту из instance.json, сервер не создаётся с пустым ключом, интервалы циклов зажаты в 1 с…7 дней (мусор в config.json не роняет поток), TEMP/PIP_CACHE_DIR чистятся, только если похожи на temp/pip-кэш, режим игры не закрывает сам GameHub и msedgewebview2.
- В репозиторий не попадают data/, build/, dist/, .venv; в тестовых файлах не должно быть личных данных (Steam ID заменён нулями).
- Список «что закрывать» по умолчанию пустой — у каждого свой.
